디자인 인계 문서

밝은 리서치 작업대와 편집형 뉴스룸을 방향으로 한 새 UI 후보입니다. 이 문서는 개발 인계용이며, F-ID와 컴포넌트 이름은 사용자 화면에 표시하지 않습니다.

인터랙티브 프로토타입 열기
화면의 기사와 AI 결과는 시연용 예시입니다. 인증, 실시간 협업, 뉴스 수신, 링크 요약, AI 정리, 사진 업로드는 모두 브라우저 안의 시뮬레이션이며 외부 요청을 보내지 않습니다.

0-1. 다크 테마 — 제안

사용자 메뉴의 ‘다크 모드’ 항목으로 전환하고 브라우저에 선택을 기억합니다(프로토타입은 localStorage, 키 moyobom-theme). 확정 기능이 아닌 제안이며, 사용자 메뉴 항목 추가·저장 위치(계정 vs 기기)·OS 설정 연동은 추가 결정이 필요합니다. 협업 보드 화면에는 사용자 메뉴가 없어 내 보드·뉴스에서 전환합니다.

구현: 모든 색은 var(--{fg|bg|line}-토큰)으로 참조하고 :root[data-theme="dark"]에서 값만 바꿉니다. 같은 색이라도 글자(fg)·면(bg)·선(line) 용도에 따라 다크 값이 다릅니다. 캔버스도 어둡게, 바탕은 보라 기운의 짙은 회색, 메모는 어두운 크림입니다. 카카오·네이버 버튼 색과 흰 로고 마크는 두 테마 공통입니다.

5. 실제 구현 시 주의할 점

  • 팬·줌과 좌표: 카드 좌표는 월드 좌표로 저장하고 화면 = 월드 × zoom + offset. 드래그 이동량은 화면 이동량 ÷ zoom. 줌은 커서 위치 기준(0.4–1.6).
  • 드래그 구분: 빈 캔버스 드래그 = 팬, 카드 드래그 = 이동, 4px 미만은 클릭. 카드 안 버튼·링크·textarea에서 시작한 포인터는 드래그로 처리하지 않음. react-konva에서는 Stage draggable과 카드 Group draggable을 분리.
  • 피드 → 캔버스: 드롭 좌표를 월드 좌표로 변환. 같은 동작을 ‘추가’ 버튼(키보드 가능)으로도 제공하고 뷰포트 중앙에 배치.
  • 긴 기사 제목: 카드 3줄, 피드 전체 표시, 상세 패널 전체. 카드 높이가 내용에 따라 달라지므로 자동 정렬은 실측 높이 사용.
  • 비동기 저장: 이동은 낙관적 반영 후 실패 시 이전 좌표로 애니메이션 복원. 추가 실패 시 임시 카드 제거 + 재시도, 삭제 실패 시 카드 복원. “동기화됨”은 성공 응답 후에만.
  • 초대 복귀: 비로그인 초대 진입 시 초대 경로를 보존하고 로그인·가입 성공 후 그 경로로 돌아와 검증 → 참여.
  • 권한: 참여자에게 이름 변경·삭제·초대 관리·내보내기를 숨김(비활성 노출 아님). 서버에서도 동일하게 거부.
  • 새 기사 유입: 받은 항목은 대기 목록에 두고 사용자가 펼칠 때 삽입해 스크롤 위치가 밀리지 않게 함.
  • 삭제와 늦은 이벤트: 삭제된 카드 id에 대한 이후 이동 이벤트는 무시해 카드가 되살아나지 않게 함(시연 도구 ‘다른 참여자가 카드 삭제’에서 재현).
  • AI 제안과 정렬 분리: 분석 결과 수신은 좌표를 바꾸지 않음. ‘자동 정렬’에서만 좌표 저장, 직전 좌표는 복원용으로 별도 보관.
  • 사용자 화면에는 version, seq, itemId, 이벤트명, 저장소 키 등 내부 용어를 노출하지 않음.

7. 확장 아이디어 (기본 범위 밖)

  • 예약 다이제스트(F-09): 보드 더보기 메뉴에서 주기를 정하고, 새로 수집된 관련 기사를 이메일로 요약. (실제 구현은 다름: 사용자별 구독 최대 3개·카테고리/키워드·매시 정각, 이메일 없이 앱 안 알림함, ‘지금 받아보기’)
  • 수동 연결선(F-10): 선택한 카드의 메뉴에서 ‘연결’을 눌러 다른 카드와 잇는 방식. 기본 도구 모음에는 넣지 않음. (실제 구현은 다름: 도구 막대의 ‘연결선’ 모드에서 카드 두 장을 차례로 누름, 선 선택 후 삭제)
  • 보드 질의응답(F-12): AI 정리 패널 하단의 보조 입력으로, 답변마다 근거 카드를 표시. 채팅 화면을 주 UI로 만들지 않음. (실제 구현은 다름: 도구 막대 ‘질문하기’로 여는 오른쪽 창, 출처 번호와 ‘보드에서 보기’)
  • 반대 관점 기사 추천(F-13): AI 그룹별로 ‘다른 시각의 기사’ 후보를 제안. 진위·중립성 판정 표현은 쓰지 않음.
